# Vérification T3.4a

Le 9 octobre 2026, un profil privé temporaire avec `local-token` vide a servi `GET /ui/admin/status` sans en-tête et répondu HTTP 200. Le processus a été arrêté et le profil temporaire effacé. Ce résultat est le témoin rouge de T3.4a, pas une validation.

Les tests ajoutés ont d'abord donné deux échecs attendus : l'API acceptait un jeton configuré vide et un fichier absent ne produisait pas `E_TOKEN`. Après correction, les deux fichiers ciblés passent (12 tests) et le typecheck passe. `DropHome` refuse absent/vide/blanc, le démarrage charge le jeton avant le relais, et l'API refuse la valeur attendue ou présentée vide. Les cas API, UI, SSE et jeton valide sont couverts.

Vérification complète après correction : `pnpm -r lint && pnpm -r typecheck && pnpm -r test` a réussi (343 tests, 36 fichiers). `openspec validate t3-4a-empty-local-token-auth --strict` a réussi. `openspec-guard` a validé les 5 scénarios liés de la change et la vérification des specs canoniques (423 critères : 146 liés, 258 dans la baseline, 19 ignorés). La mise à jour requise de la baseline a produit +0/-0 ligne.

Essai du binaire groupé : avec un `local-token` vide dans un profil privé temporaire, `drop serve` quitte avec le code 1 et `E_TOKEN` avant toute écoute sur le port 17886. Avec un jeton valide sur le port 17887, `GET /ui/admin/status` répond 200 avec `Bearer` et 401 sans jeton. Les processus et profils temporaires ont été supprimés.

Relecture ciblée du diff et des appelants : le jeton est lu avant `RelayClient.start`, la comparaison refuse une valeur attendue ou reçue vide, et les routes API/UI/SSE restent derrière `authorized`. Les seules routes publiques existantes sont la carte A2A et la santé de la coque Mac ; elles ne donnent pas accès aux actions administratives. Aucun contournement nouveau relevé dans ce périmètre. Cette relecture séquentielle ne remplace pas la revue indépendante exigée.

La tentative `codex review --uncommitted` a échoué avant analyse : HTTP 400, modèle configuré non accepté par le compte du poste. Une seconde tentative avec un autre modèle a échoué de la même manière. Le lancement de `/review` gstack a donc été interrompu, sans résultat de revue. L'audit `/cso --diff --code --offline` a créé le run `1791564406499-c7da705180113a61`, puis s'est terminé `partial` : son diff contre `origin/main` inclut de nombreux travaux antérieurs et ses entrées d'historique étaient indisponibles. Aucun rapport complet de sécurité n'est revendiqué. Blocage outillage signalé sous `9c715b93-dd11-4d25-90a8-c3c24ec87a74`.

Nouvelle vérification ciblée le 9 octobre : `pnpm exec vitest run packages/node/test/api.test.ts packages/node/test/local-token.test.ts` passe (13 tests, 2 fichiers). Trois spécialistes de la revue gstack (sécurité, tests, maintenabilité/API) et une contre-revue adversariale ont inspecté le seul diff T3.4a : aucun défaut concret. La contre-revue a vérifié la lecture du jeton avant le relais, le refus avant `listen`, les routes protégées, les deux routes publiques préexistantes et le parcours valide. Elle a relevé que le test seul ne prouve pas directement l'absence de listener ; l'ordre du code et l'essai du binaire sur port 17886 apportent cette preuve. La spec a été précisée pour mentionner le `?token=` déjà utilisé par l'UI et son flux SSE.

Nouvel audit `/cso --diff --base HEAD --code --offline`, run `1791567885700-ebe8013a38ab1992` : aucun constat étayé ; modèles d'application, surface d'attaque, OWASP A01/A07/A10, STRIDE et classification des données évalués sur les chemins de code concernés. Le rapport global reste `partial` car l'outil signale comme non lus des icônes/images et deux anciennes specs sans lien avec T3.4a, ainsi que l'absence de reproduction exécutée *par l'outil*. La reproduction avant/après et le binaire réel ont été exercés séparément et consignés ci-dessus. Cette limite ne réduit pas la couverture des fichiers source modifiés de T3.4a. La passe Codex externe facultative de gstack reste indisponible sur ce poste ; elle n'est pas utilisée comme preuve.

Les constats précédemment ouverts R-1 et R-2 sont clos pour T3.4a sur la base des tests, de l'essai du binaire et des quatre relectures indépendantes. La spec canonique `node` reprend désormais tout le bloc modifié sans supprimer d'autre scénario. `openspec validate --specs` passe (16 specs), tout comme la validation stricte de la change. Le garde canonique final couvre 426 critères : 151 liés par sélecteur, 256 gelés dans la baseline et 19 ignorés ; la mise à jour de baseline ne retire que deux anciennes entrées (+0/-2). Après cette synchronisation, lint, typecheck et les 343 tests des 36 fichiers passent à nouveau.

Recette manuelle courte, si souhaitée : dans un profil de test isolé, vider `local-token` puis lancer `drop serve` et constater `E_TOKEN` sans API locale ; restaurer un jeton valide, relancer et vérifier que le panneau et `/ui/admin/status` demandent ce jeton. Cette recette n'est pas nécessaire pour établir la correction technique déjà exercée par le binaire groupé, mais permet de la constater dans l'environnement de l'utilisateur.
