Quand la suite du travail
se trouve chez quelqu'un d'autre.

Un collègue a le contexte. Son agent a les outils. drop organise le passage de la question à la réponse.

01 / La demande

Poser une question précise.

L'agent choisit une action dans un catalogue : résumer des erreurs, interroger un dépôt ou une source déjà connectée.

02 / La décision

Voir ce que l'on autorise.

Le propriétaire lit la raison, les informations attendues et le coût annoncé. Il décide pour cette demande.

03 / Le retour

Continuer avec la réponse.

La sortie est contrôlée. Pour les capacités sensibles, elle est aussi relue avant d'arriver chez le demandeur.

Interroger un dépôt

Une réponse à partir de fichiers autorisés. Le propriétaire relit le résultat avant de le transmettre.

⌘

Retrouver le contexte d'un outil

mcp.answer

Une question sur une source déjà connectée : maquettes, tickets ou documentation. Les outils sont choisis par le propriétaire.

Les intégrations réelles chez les testeurs restent à valider. Lire les preuves disponibles.

Partager une réponse reste une décision.

Le cadre de l'échange est fixé avant l'exécution. Le modèle travaille à l'intérieur de ce cadre.

Comprendre les frontières de confidentialité

Le relais transporte du contenu chiffré.

Il route les enveloppes entre les Nodes sans lire leur contenu. Les métadonnées de routage restent visibles.

Les outils sont choisis à l'avance.

La question du demandeur ne peut pas ajouter un outil à la liste autorisée.

Le choix du modèle compte.

Un modèle distant reçoit le contexte nécessaire à ses appels. Exécution chez le propriétaire ne signifie pas traitement entièrement local.
